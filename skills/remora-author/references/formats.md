# Форматы Remora и публикация

Это контракт реализованного агентского API, а не список всех возможностей кабинета.
Если схема подключённого инструмента отличается, проверь актуальный контракт, не подбирай
неизвестные поля вслепую.

## Что можно передать

| Материал            | Представление                                                   |
| ------------------- | --------------------------------------------------------------- |
| Набор               | `title`, `description`, `lang_term`, `lang_definition`, `cards` |
| Карточка            | обязательные `term` и `definition`; дополнительные поля ниже    |
| Курс                | `title`, `description`, `sections`                              |
| Раздел              | `title`, `articles`                                             |
| Статья              | `title`, `body`, `material` (один полный набор)                 |
| Изменение структуры | отдельный контракт с `set_id`, без `material`; см. api.md       |

Дополнительные поля карточки:

- `content_type`: `text`, `latex` или `code`; для кода — `code_language`.
- `hint`, `alt_answers`, `term_transcription`, `definition_transcription`.
- `wrong_term_answers`, `wrong_definition_answers`: массивы строк, до 30 на сторону.
- `term_image_id`, `definition_image_id`: UUID уже загруженных собственных изображений.
  Сначала вызови `upload_image` с публичным HTTPS URL или base64, затем подставь полученный ID.
- `id`: только для сохранения существующей карточки при обновлении; новым не назначай ID.

Карточки не имеют отдельных полей для сложности, источника, объяснения ответа, аудиофайла,
cloze-шаблона или выбора направления. Источник помещай в description/body; развёрнутое
объяснение — в body. Не отправляй такие дополнительные поля в надежде, что они сохранятся.

## Отображение

Карточки поддерживают обычный текст, LaTeX и код через `content_type`. Не считай, что любой
Markdown будет интерпретирован как в статье. Режим карточки общий для обеих сторон.

Теория в `body` поддерживает заголовки, выделение, списки, таблицы, цитаты, разделители,
безопасные ссылки, inline/fenced-код и формулы KaTeX. Изображение вставляется только ссылкой
`![описание](media:UUID)`, которую возвращает `upload_image`; внешний URL напрямую не рендерится.
HTML, iframe и исполняемый код запрещены.

PDF, DOCX, TXT, заметки и веб-страницы могут быть источниками, если агент умеет и имеет право
их читать. MCP не принимает исходный документ: сначала извлеки содержание средствами агента,
затем передай структурированный текст. Импорт Anki/Quizlet, файловый экспорт и обучение через
кабинет — не дополнительные MCP-инструменты. Не обещай импорт файла через create_course.

## Размеры

Название набора/курса/статьи/раздела: до 160 символов. Описание: до 5000.
Сторона карточки: до 10 000; подсказка: до 1000; транскрипция: до 300;
`code_language`: до 50; языковой код: 2–10 символов; `alt_answers`: до 30 элементов.
Курс в одном запросе: до 50 разделов, 100 статей суммарно, 5000 карточек суммарно,
100 000 символов на статью, 1 000 000 символов теории суммарно.
Это технические пределы, а не рекомендуемый учебный объём. При превышении согласуй деление
на курсы; не обрезай материалы молча и не выдавай частичное создание за полное.

## Публикация

1. Публичная единица каталога — курс. Новый курс остаётся неопубликованным, но новые наборы,
   включая созданные внутри курса, публичны по умолчанию и доступны по своему slug. Контракт
   агента не принимает `visibility` и не предоставляет отдельной публикации набора. Если запрос
   подразумевает приватное хранение карточек, предупреди об этом до создания. Для появления
   материала в каталоге оформи и опубликуй курс; не дублируй существующие карточки без
   необходимости.
2. Нужна явная просьба пользователя открыть материал публично и scope `courses:publish`.
   Наличие права у токена не является разрешением. Если инструкция двусмысленна, создай только
   неопубликованный курс или уточни именно публикацию курса.
3. До вызова проверь непустой курс со статьями и карточками у каждой статьи. Пустые черновики
   допустимы при создании, но не готовы к публикации. Проверь источники и отсутствие личных
   данных/приватных фрагментов, не предназначенных для публичного размещения.
4. `publish_course(course_id, publication={"tags": [...]}, request_key=UUID)`.
   Теги независимые, не дерево категорий: например `["математика", "линейная алгебра"]`.
   До 20 тегов, каждый 1–60 символов; буквы, цифры, пробелы, дефис и подчёркивание.
   Пустой список допустим контрактом. Не выдумывай поля `subject`, `category` и `visibility`.
5. Прочитай результат: проверь `is_published`; не обещай каталог без проверки `is_listed`.
   Для кабинета используй настроенный base URL с сохранением префикса `/app`, если он есть.
   Не составляй публичную ссылку по непроверенному шаблону; верни ID, если маршрут неизвестен.

Редактирование опубликованного курса агентом требует отдельного снятия публикации.
Не выполняй его автоматически: это закрывает публичный доступ. Ошибки публикации не являются
основанием создавать дубликат курса. Правила revision и повторов — в api.md и SKILL.md.
